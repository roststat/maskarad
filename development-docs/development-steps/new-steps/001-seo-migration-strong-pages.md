# 001 — SEO-миграция сильных страниц

## Зачем

Старый сайт `maskarad-teatr.ru` имеет поисковую ценность в отдельных URL спектаклей, услуг и праздников. Их нельзя сваливать только в общие разделы: сильные страницы нужно превратить в новые посадочные или закрыть точными 301-редиректами.

## Границы

Делаем:

- инвентаризацию приоритетных старых URL;
- новые посадочные страницы для сильных спектаклей, услуг и праздников;
- уникальные title/description, FAQ, CTA и внутренние ссылки;
- карту `старый URL → новый URL`;
- обновление sitemap;
- проверку сборки и локальных редиректов.

Не делаем:

- перенос домена до проверки;
- CMS;
- онлайн-оплату;
- финальную форму заявки без решения по каналу доставки;
- массовую публикацию контента без проверки актуальности владельцем.

## Подшаги

1. 001-1 — зафиксировать список уже созданных SEO-посадочных и редиректов.
2. 001-2 — выбрать следующий набор URL: спектакли, услуги или типы праздников.
3. 001-3 — достать контент из старого сайта или архива, если доступен.
4. 001-4 — создать/уточнить посадочные страницы и метаданные.
5. 001-5 — обновить редиректы, sitemap и внутренние ссылки.
6. 001-6 — проверить сборку, страницы, редиректы и мобильную версию.

## Приёмка

Шаг считается закрытым, когда:

- для согласованного набора старых URL есть новая судьба: посадочная, общий раздел, частичный перенос, 301 или исключение;
- старые сильные URL не ведут на случайные общие страницы, если нужна отдельная посадочная;
- `npm run build` проходит;
- sitemap содержит новые посадочные;
- выборочно проверены редиректы старых URL.

## Доказательства

Минимум два доказательства из разных плоскостей:

- техническое: `npm run build`;
- маршрутизация: `curl -I` для новых страниц и старых URL;
- SEO-структура: проверка `sitemap.xml`;
- визуальная проверка: локальная или Vercel-версия на desktop/mobile.

## Риски

| Риск | Как снижаем |
|---|---|
| Нет архива старого сайта | Делаем структуру и черновые тексты, но помечаем необходимость точного контента |
| Устаревшие цены/услуги | Перед финальной публикацией просим владельца подтвердить актуальность |
| Потеря SEO из-за широких редиректов | Приоритетные URL выносим выше wildcard-правил |
| Дублирование стартерной и проектной документации | `development-docs` хранит процесс, `PROJECT_PASSPORT.md` и SEO-документы остаются источниками продуктового контекста |
