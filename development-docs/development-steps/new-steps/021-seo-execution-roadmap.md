## Как выполнять один подшаг

1. Запустить sync-check, прочитать паспорт, текущую работу и план шага. Перед кодом Next.js прочитать применимый локальный guide. Если ветка/production устарели, сначала определить актуальное состояние.
2. В `current-steps.md` указать активный подшаг, входные данные и конкретный ожидаемый результат. Проверить сведения аудита на затрагиваемых адресах.
3. Выполнить ограниченную задачу; сохранить URL, источник фактов, условия и выбранные решения. При отсутствии факта запросить его и продолжать независимую часть.
4. Получить два подтверждения из разных плоскостей: например сборка/типы + браузер, API + тестовое хранилище, схема данных + проверка источника. Для документов — структурная проверка + сверка покрытия стратегии.
5. Записать итог `completed-steps/NNN-K-<result>.md` по форме; обновить `current-steps.md` и соответствующие строки реестра. При неполной проверке указать предел результата, не писать «опубликовано» или «готово» без доказательства.
6. Для изменения приложения выполнить необходимые проверки проекта и согласованный маршрут выпуска. После публикации проверить публичное содержимое/код ответа и свежесть версии. Не считать локальную сборку доказательством production.
7. Закончить шаг с отчётом `reports/NNN-<feature>-report.md`; выбрать следующий исполнимый подшаг. Нет необходимости заново согласовывать каждую обратимую работу из утверждённой очереди; внешние расходы, неподтверждённые факты и новые условия сервиса требуют конкретных входных данных.

## Ограничения и готовность к выпуску

- Факты, цены, длительность, вместимость, отзывы, права на медиа и опыт конкретного мероприятия подтверждаются источником. Неизвестное отмечаем явно; пустое поле не заполняем предположением.
- Старые полезные URL и редиректы сохраняем. Новый URL требует самостоятельной задачи/объекта и проверки пересечения с существующими страницами.
- Существующие страницы обновляем по 009: максимум один содержательный URL в выбранный день. Блокирующие технические ошибки исправляем отдельным подшагом без ожидания дня переписывания текста. Новый каталог публикуем по собственному небольшому выпуску.
- Секреты и боевые данные не трогаем без прямого подтверждения владельца. Тестирование форм — только на изолированных синтетических данных; контакты не передаём аналитике.
- Каталоги начинают с модерируемых данных, без обязательных кабинетов, онлайн-оплаты и CRM. CMS/новое хранилище оцениваем только при доказанной необходимости и фиксируем решение в паспорте.
- Платные публикации включаются после выбора конкретного размещения, бюджета и способа оценки. Покупка ссылок для передачи поискового веса и накрутка не являются заданиями этой очереди.
- Отменённые рекламные заглушки, ИИ-бриф и PDF не возвращаем. Новый помощник работает с выбором из каталога и оценивается по пользе.

## Ориентиры времени и объёма

Первые 90 дней стратегии: исправления и измерение, усиление действующих страниц, пилот площадок/исполнителей, первые материалы и оценка. График 009 до 8 декабря 2026 остаётся действующим. Шаги 034–035 запускаются по готовности базы, а не обещаются к фиксированной дате.

35–51 новых URL — сценарий мощности: 20–25 мест, 5–8 исполнителей, 4–8 категорий/посадочных/подборок суммарно, 6–10 новых статей/реальных кейсов. 37 обновлений не увеличивают число страниц; категории и подборки не считаем дважды. Меньший проверенный пилот допустим при недостатке фактуры. Доходность, частотность и целевой рост определяются по данным 023–024 и результатам 036.
