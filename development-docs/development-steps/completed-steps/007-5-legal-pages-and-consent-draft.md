# 007-5 — Проекты документов и согласия в формах

> Следующий подшаг 007-7 изменил поток заявки: вместо внешнего webhook используется закрытое хранилище на сервере. Актуальное состояние — в `007-7-local-lead-storage-and-owner-view.md` и `current-steps.md`.

Результат: обе формы требуют отдельную пустую по умолчанию галочку, а `/api/leads` отклоняет запрос без актуальной версии согласия; четыре проекта документов доступны по ссылкам из подвала.

## Доказательства

- `npm run lint` и `npm run build` завершились успешно; собраны 132 статические страницы.
- `legal:predeploy` включён в `seo:predeploy` и останавливает публикацию документов с незаполненными реквизитами или черновой версией согласия.
- Локальные HTTP-запросы вернули `200` для `/privacy-policy`, `/personal-data-consent`, `/cookie-policy`, `/terms`; тест API без согласия вернул `400`. На локальной главной `Set-Cookie` в ответе не обнаружен.

## Ограничения

- Владелец предоставил и подтвердил почтовый адрес, email, ИНН, срок хранения 3 года и сообщил об отправке заявок в собственный Telegram-бот. Дата утверждения и правовая/техническая проверка маршрута остаются открытыми. Это проекты, соответствие требованиям закона пока не подтверждено.
- Положительный тест отправки не проведён: автоматическая проверка разрешений отклонила запрос с реальным телефоном из-за возможной передачи в Telegram. Реальные заявки и секреты не использовались.
- Нужны проверка уведомления Роскомнадзора, фактического места хранения заявок и возможной трансграничной передачи через Telegram или посредника.

## Источники для юридической проверки

- [152-ФЗ, статья 9 и другие требования к согласию](https://mintrud.gov.ru/docs/laws/130).
- [152-ФЗ, статьи 18, 18.1 и 22: обязанности оператора](https://mintrud.gov.ru/docs/laws/130).
- [Роскомнадзор: обязанности оператора сайта и уведомление](https://82.rkn.gov.ru/directions/pers/p15375/). Страница ведомства старая; перед подачей уведомления требуется сверить действующую редакцию закона и актуальную форму.
