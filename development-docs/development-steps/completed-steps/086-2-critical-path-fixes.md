# 086-2 — устранены причины сдвига и лишней доставки фото

1 ноября 2026. Результат одной строкой: место хлебных крошек резервируется CSS из серверного HTML; портретные мини-фото используют лёгкие производные, popup сохраняет оригиналы.

`body:has(.breadcrumbs)` заменяет отступ, появлявшийся только после JS-класса; эффект класса удалён. На всех четырёх локальных шаблонах Lighthouse CLS = 0 вместо стабильных 0,04146 публичной базы. Это устранение конкретной причины, не отключение анимаций/блоков для баллов.

43 портретных фото получили версионированные миниатюры с тем же ориентиром кадрирования center 30%; зимняя contain-подборка использует оригиналы. Генератор `scripts/performance/build-mini-thumbnails.mjs` воспроизводит crop и хешированные имена. Оригиналы не перезаписаны, Popup получает исходный массив, сохраняются alt и размеры. Новые файлы можно кешировать год, при изменении источника/параметров меняется URL.

Точные Next Image проверки при одинаковом w=384/q=65: photo-063 37 306 → 16 386 байт, photo-076 43 412 → 16 280 (−56/62%). Hero главной 48 486 → 42 640, корпоративной 76 846 → 68 396 при том же 750w. [Ответы/Cache-Control](../../reports/086-image-delivery-check.json), [манифест](../../reports/086-mini-thumbnails.json).

У Article задан sizes и eager/high вместо deprecated priority; hero-фото используют качество 65 из уже разрешённого списка. Прежний запрос статьи w=1920 не означал доставку настоящих 1920 пикселей: исходник 640×459, Next не увеличивал его. Выигрыш подтверждён фактическими байтами (38 306 → 33 452), а не отношением заявленных ширин. Контент и sitemap lastmod не менялись.
