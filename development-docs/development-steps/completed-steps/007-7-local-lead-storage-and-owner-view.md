# 007-7 — Локальное хранилище заявок и просмотр владельца

Результат: `/api/leads` больше не вызывает внешний webhook, а сохраняет заявку с отметкой о согласии в отдельном закрытом каталоге. `/admin/leads` показывает заявки только после Basic Auth с отдельным сильным паролем, хэш которого хранится в окружении сервера.

## Доказательства

- `npm run lint` и `npm run build` прошли; маршрут `/admin/leads` включён в production-сборку.
- Локальный API отклонил синтетическую заявку без согласия (`400`) и сохранил заявку с согласия (`200`); доступ к `/admin/leads` без пароля и с неверным паролем вернул `401`, с тестовым паролем — `200` и вымышленную запись.
- Каталог тестового хранилища имел права `0700`, файл — `0600`; скрипт удаления убрал синтетическую запись с истёкшим трёхлетним сроком, свежую запись сохранил.
- `npm run leads:check` прошёл на отдельном тестовом каталоге и валидном синтетическом хэше; `/admin/leads` повторно проверен с валидным форматом хэша (`401` без пароля, `200` с паролем).
- Поиск по публичному коду формы и API не нашёл вызовов webhook и названий мессенджеров; запасное действие WhatsApp удалено.

## Граница результата

Production не изменён. На сервере ещё нужно настроить `LEAD_STORAGE_DIR`, `LEAD_ADMIN_PASSWORD_HASH` и ежедневный запуск очистки, проверить расположение сервера и резервные копии. Владелец ранее запретил просмотр серверной конфигурации, поэтому эти факты не заявлены как проверенные.
