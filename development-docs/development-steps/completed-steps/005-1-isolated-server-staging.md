# 005-1 — Изолированный серверный staging-контур

## Результат

На сервере создан независимый контур сайта:

- код и зависимости расположены в `/opt/maskarad/app`;
- отдельный процесс PM2 называется `maskarad-site`;
- приложение слушает только `127.0.0.1:3200`;
- каталоги, порты и Nginx-конфигурации Fractera/«Автозаботы» и Maxflok не изменялись.

`maskarad-teatr.ru` и `www.maskarad-teatr.ru` на момент проверки указывают на другой IP-адрес, поэтому публичный Nginx-виртуальный хост и TLS-сертификат намеренно не создавались. Это исключает случайное переключение посетителей до готовности DNS.

## Доказательства

- На сервере `npm run seo:predeploy` прошел успешно: 163 старых URL покрыты, аудит 179 редиректов, alt, TypeScript и production-сборка 128 статических страниц.
- `curl -I http://127.0.0.1:3200/` и `/sitemap.xml` вернули `200 OK`; `/detskie-prazdniki/film.html` вернул `308` на `/stati/semka-filma-s-detmi-na-prazdnike`.
- `pm2` подтвердил: `maskarad-site`, `maxflok-site` и `fractera-app` имеют статус `online`; у нового процесса `0` рестартов.

## Наблюдение

`npm ci` сообщил об одной критической уязвимости зависимостей. Автоматическое исправление не запускалось: оно может изменить lockfile и требует отдельного аудита.
