# Маскарад — Next.js сайт

Сайт детского выездного театра «Маскарад» на собственном сервере.

Production: https://maskarad-teatr.ru/

## Локальная работа

Перед началом сессии:

```bash
bash scripts/server/sync-check.sh
```

После проверки свежести читать:

1. `AGENTS.md` — правила работы агента в проекте.
2. `development-docs/PASSPORT.md` — рабочий паспорт проекта по системе стартера.
3. `development-docs/development-steps/current-steps.md` — текущий шаг и ближайшее действие.
4. `PROJECT_PASSPORT.md`, `MIGRATION_PLAN.md`, `POSITIONING_AND_SEO_STRATEGY.md` — продуктовый контекст Маскарада.

```bash
npm install
npm run dev
```

Локальный порт проекта «Маскарад» зарезервирован как `4310`, чтобы не конфликтовать с другими проектами на `3000`, `3001` или `3002`.

Локальный адрес:

```text
http://localhost:4310
```

Production-проверка:

```bash
npm run build
```

Проверка перед деплоем:

```bash
npm run seo:predeploy
```

Она проверяет готовность юридических реквизитов, покрытие старых URL, карту 301-редиректов, `alt` у изображений, TypeScript и production-сборку. Пока дата утверждения и версия согласия помечены как черновые, `legal:predeploy` намеренно останавливает публикацию.

После публикации на домене:

```bash
npm run seo:prelaunch -- https://maskarad-teatr.ru
```

Проверка `12/12` подтверждает SEO-ответы, но не доказывает, что сервер запустил последний коммит. Свежесть версии нужно сверять отдельно.

## Канал заявок

Обычная форма и окно «Написать организатору» отправляют данные в единый `/api/leads`. API сначала сохраняет заявку в закрытом каталоге сервера вне Git-репозитория, затем доставляет её через MAX Bot API владельцу. Для production требуется настроить переменные окружения процесса сайта:

```text
LEAD_STORAGE_DIR=/opt/maskarad/private/leads
LEAD_ADMIN_PASSWORD_HASH=<соль:хэш>
MAX_BOT_TOKEN=<токен платформы MAX>
MAX_CHAT_ID=<ID закрытого чата или группы>
NODE_EXTRA_CA_CERTS=/opt/maskarad/app/certificates/russian-trusted-root-ca.pem
```

На текущем Timeweb VPS владелец подтвердил регион РФ; каталог `/opt/maskarad/private/leads` создан вне приложения с правами `0700`, файлы создаются с правами `0600`. Каталог нельзя помещать внутрь `/opt/maskarad/app`: автодеплой обновляет рабочее дерево. Без настроенного хранилища API возвращает `503`, а форма предлагает звонок или копирование текста.

Бот создаётся на платформе MAX для партнёров после верификации профиля ИП и модерации бота; только после этого платформа выдаёт токен. Для доставки в группу добавьте бота в закрытую группу администратором и отправьте в ней тестовое сообщение. Затем временно задайте токен только в текущем терминале и выполните `npm run leads:max-discover-chat`: команда покажет `chat_id`, но не выводит токен и содержимое сообщений. Сохраните найденный ID как `MAX_CHAT_ID` в закрытой конфигурации production.

После настройки от имени пользователя приложения выполнить `npm run leads:check`: команда проверяет путь, права, наличие хэша пароля и формат MAX-переменных, не выводя секреты и заявки. Должен быть задан ровно один получатель: `MAX_CHAT_ID` или резервно поддерживаемый `MAX_USER_ID`. `npm run leads:max-test` проверяет контракт доставки без обращения во внешний сервис; `npm run leads:max-send-synthetic` отправляет одну явно тестовую заявку без реальных персональных данных в настроенную группу.

После публикации кода закрытые значения на текущем VPS задаются командой `bash scripts/server/configure-max-production.sh`. Она спрашивает токен скрытым вводом, передаёт его на VPS только внутри SSH-соединения, атомарно обновляет закрытый `.env.production`, передаёт `NODE_EXTRA_CA_CERTS` в окружение до старта Node, перезапускает только `maskarad-site` и сохраняет состояние PM2. Секреты в аргументы команд, Git и вывод не попадают.

Пароль владельца и его хэш не хранить в репозитории. Скрипт `node scripts/server/create-lead-admin-password.mjs` создаёт случайный пароль и значение для `LEAD_ADMIN_PASSWORD_HASH`; запускать его в приватном терминале и сохранить пароль в менеджере паролей. Заявки открываются по `/admin/leads` через HTTPS и Basic Auth с логином `owner`; страница не кэшируется и не индексируется. API принимает заявку только с актуальной версией отдельного согласия, которая записывается вместе со временем сервера.

На VPS установлен `maskarad-leads-purge.timer`, который ежедневно запускает `node scripts/server/purge-leads.mjs` с той же `LEAD_STORAGE_DIR`. Скрипт удаляет записи старше трёх лет; удаление проверено на пустом синтетическом файле. Политику резервных копий провайдера ещё нужно подтвердить. Группа MAX должна быть закрытой; токен бота и ID получателя нельзя помещать в Git, клиентский код или отчёты. По официальной документации запросы направляются на `platform-api2.max.ru`. Для Node-процесса указан отдельный официальный корневой сертификат Минцифры через `NODE_EXTRA_CA_CERTS`; системное хранилище macOS не изменяется, отключать проверку TLS запрещено. Файл взят с официального домена Госуслуг `gu-st.ru`, проверяемый SHA-256 отпечаток: `D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31`.

Если MAX не настроен, заявка продолжает сохраняться в закрытом серверном каталоге. Если MAX настроен, но доставка не удалась, API сообщает форме о сбое, а сохранённая серверная копия остаётся доступной владельцу. Перед включением канала нужно утвердить обновлённые документы и проверить сведения оператора о передаче данных российскому получателю ООО «МАХ».

## Публикация на сервере

`origin/main` — источник кода для `/opt/maskarad/app` на Timeweb VPS. `maskarad-auto-deploy.timer` проверяет новые коммиты каждые две минуты, выполняет `npm ci`, `npm run seo:predeploy` и перезагружает только PM2-процесс `maskarad-site`. Nginx проксирует домен на `127.0.0.1:3200`.

При расхождении кода и публичной страницы проверять на **подтвержденном VPS**, где существует `/opt/maskarad/app`:

```bash
git -C /opt/maskarad/app rev-parse --short HEAD
systemctl status maskarad-auto-deploy.timer --no-pager
systemctl status maskarad-auto-deploy.service --no-pager
journalctl -u maskarad-auto-deploy.service -n 100 --no-pager
pm2 status maskarad-site
```

Публичный `200 OK` и успешный `seo:prelaunch` не заменяют проверку журнала автодеплоя и коммита работающего процесса. IP публичного сайта не следует автоматически считать SSH-адресом VPS.

Карта переноса старого сайта и список важных SEO-страниц лежат в `MIGRATION_PLAN.md`.

Полный паспорт проекта, правила по портам и этапы дальнейшей разработки лежат в `PROJECT_PASSPORT.md`.

Смысловая стратегия сайта, акцент на театрализованные праздники и будущие SEO-страницы описаны в `POSITIONING_AND_SEO_STRATEGY.md`.

Публично найденные материалы и идеи из Instagram `@maskarad_teatr` собраны в `INSTAGRAM_CONTENT_NOTES.md`.

## Система памяти проекта

В проект добавлена документация из стартера проектов. Она не заменяет продуктовые документы Маскарада, а задает порядок работы:

- `AGENTS.md` — постоянные правила входа в проект.
- `development-docs/PASSPORT.md` — краткий паспорт проекта с источниками фактов.
- `development-docs/development-steps/current-steps.md` — где работа сейчас.
- `development-docs/development-steps/new-steps/` — планы следующих шагов.
- `development-docs/development-steps/completed-steps/` — итоги закрытых подшагов.
- `development-docs/reports/` — отчеты по законченным фичам или крупным отказам.
- `development-docs/BACKLOG.md` — долги, которые не входят в текущий шаг.
- `development-docs/ANTI-PATTERNS.md` — короткие законы из ошибок.

Правило: решения по проекту не оставлять только в чате. После значимого решения обновлять паспорт, текущий шаг, backlog или профильный документ.
